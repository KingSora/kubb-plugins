# MCP

Generates a Model Context Protocol (MCP) server from your OpenAPI spec. Each operation becomes a typed tool that AI assistants can call.

The tool handlers call a function generated by a client plugin, and Zod schemas from `@kubb/plugin-zod` validate the tool input. Next to the handlers, the plugin writes `server.ts` with the tool registrations, a `start.ts` entry that serves the tools over stdio, and a `.mcp.json` that runs `start.ts` with `tsx`.

## Setup

- Add `@kubb/plugin-ts`, `@kubb/plugin-zod`, and a client plugin: `@kubb/plugin-fetch` or `@kubb/plugin-axios`.
- Install `@modelcontextprotocol/server` v2 or higher and `zod` 4.2 or higher in the app that runs the server, plus `tsx` to run the generated TypeScript.
- Copy the server entry from the generated `.mcp.json` into the `.mcp.json` at your project root. Its path to `start.ts` is relative to the Kubb `root`, the folder MCP clients start the server from.

## Options worth knowing

- `client` picks `fetch` or `axios` when both client plugins are registered. A single client is detected automatically.
- Keep `output.path` a folder name, such as the default `mcp`. Single-file output has no place for `server.ts`, `start.ts`, and `.mcp.json`.

## Example

```typescript [kubb.config.ts]
import { defineConfig } from 'kubb/config'
import { pluginTs } from '@kubb/plugin-ts'
import { pluginZod } from '@kubb/plugin-zod'
import { pluginFetch } from '@kubb/plugin-fetch'
import { pluginMcp } from '@kubb/plugin-mcp'

export default defineConfig({
  input: './petStore.yaml',
  output: { path: './src/gen' },
  plugins: [
    pluginTs(),
    pluginZod(),
    pluginFetch({ baseURL: 'https://petstore.swagger.io/v2' }),
    pluginMcp({ output: { path: 'mcp', mode: 'directory' } }),
  ],
})
```
